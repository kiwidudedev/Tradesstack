| Time | Observed action | Behavioural finding |
| --- | --- | --- |

| 30–42s | TradesStack worksheet is shown at about 80%, then selection moves to the populated totals area around `Z3` and later down the sheet | TradesStack renders the same broad grid interaction, formula bar and horizontal/vertical navigation affordances |

| 54–72s | TradesStack is scrolled to rows in the totals area, including cells around `AA51`/`AA57`, with currency-formatted results visible | The recording demonstrates selection/scrolling and displayed totals; it does not prove a clipboard transfer or a formatting mutation |
| 72–90s | Excel returns to the same totals region, selects formula cells such as `AA51`, and ends with the macOS capture controls visible | Excel visibly exposes the underlying formula in the formula bar for the selected total; this is the key formula-bar comparison point |

The recording contains no reliable copy/paste gesture and no independent clipboard observation. It therefore supplies visual evidence for zoom, scrolling, selection, displayed values, and formula-bar inspection, but not evidence for Excel clipboard MIME payloads or Excel-to-TradesStack transfer success.

- The user's original Excel Online workbook was inspected read-only through the authorized Chrome extension session. The observed UI included five worksheets, a formula bar, name box, ribbon clipboard/formatting controls, and a focused grid.
- A separate disposable synthetic `Book.xlsx` was used for editing tests. Live interaction verified that Excel copies `=A1+B1` from `C1` to `C3` as `=A3+B3`, evaluating to `34`; the original workbook was not mutated.
- Excel grid entry worked through native keyboard input. Browser-level synthetic paste into the Excel grid was unreliable; the repeatable live copy/paste path used Excel's ribbon controls.
- The isolated Chrome profile is now authenticated to the disposable `Book.xlsx` and is reachable by REA at `http://127.0.0.1:9228`. REA successfully listed the workbook page (`ev_42834f2f0866bc9301f420ed0bbbf046453d86e57e9c33b0e3232adf6ebdde10`), inspected it (`ev_7dc54a4d27e0f57b1e313cd0d3d1523e4ee65615a3f0c5362c362eefcd23efc0`) and captured a screenshot. Inspection is passive; REA does not click or mutate the workbook.
- Excel's live formula-copy case is evidenced by the authorized computer-use session; the live Excel-to-TradesStack clipboard handoff and direct MIME enumeration remain unverified because that browser-control surface does not expose clipboard reads and REA's browser operations are passive-only.
- External Excel formula reference translation remains inherently limited when the clipboard representation does not expose the copied range's source coordinates. TradesStack-to-TradesStack copies use the structured MIME payload to preserve this information.
- A local clipboard-inspector page received the actual system clipboard after Excel Online ribbon Copy. The browser exposed only `text/plain` and `text/html` to the receiving page for this synthetic range. `text/plain` was `20\t20\t20\r\n60\t30\t30`; `text/html` was 1,759 bytes with Excel class-based style rules and no formula/source-coordinate attributes on the sampled cells. Excel-specific binary formats were not exposed to the page in this browser path.
- Because the real external payload did not expose formula text or copied source coordinates, TradesStack cannot safely reconstruct or translate the original formulas. It retains formulas when an accessible clipboard representation explicitly supplies them, and otherwise imports the displayed values plus supported HTML styles without fabricating formula data.
